## 1. 🎯 Project Overview & Core Mission

### The Business Problem
When accountants or businesses export DayBooks, Vouchers, or Masters from **Tally Prime / Tally ERP 9** and import them into another company (or a merged company):
1. **Accidental Overwrites:** Tally uses internal unique IDs (`GUID`, `MASTERID`, `REMOTEID`, `VCHKEY`, `ALTERID`). If a voucher with an existing ID already exists in the destination company, Tally **overwrites** and replaces the existing transaction instead of creating a new voucher.
2. **Opening Balance Corruption:** When importing Masters along with transactions, existing party ledger balances and stock item opening quantities in the destination company get wiped out or overwritten by the exported file's opening balances.
3. **Company Lock:** The exported XML often binds to a specific company via `<SVCURRENTCOMPANY>`. If imported into a company with a different name, errors or inconsistencies arise.

### The Solution
This tool processes exported Tally XML files to:
- Strip out all internal database IDs, forcing Tally to treat every transaction as a brand-new `ACTION="Create"` entry.
- Cleanly reset/strip opening balances and stock batch allocations so existing financial books remain untouched.
- Strip hard-coded company locks.
- Preserve Tally's strict encoding (**UTF-16LE with BOM** or **UTF-8**) without corrupting characters or structure.
- Run **100% client-side** inside the browser for absolute data privacy (accounting data never leaves the client machine).

## 3. 🔍 Deep Dive: XML Tags Cleaned & Why

Every regex and replacement in this project exists to solve a specific Tally behavior. **Do not remove or alter these rules without reading this section.**

### 3.1 Voucher Header Attributes
* **Attributes:** `REMOTEID="..."`, `VCHKEY="..."` inside `<VOUCHER ...>`
* **Why:** In Tally XML, voucher tags look like:
  ```xml
  <VOUCHER REMOTEID="5c4ef572-1f1f-4f24-950f-f883892881b1-0000a12b" VCHKEY="5c4ef572-1f1f-..." ACTION="Create" VCHTYPE="Sales">
  ```
  If `REMOTEID` or `VCHKEY` matches an existing entry, Tally performs an `Alter` instead of `Create`.
* **Action:** Strip both attributes, leaving:
  ```xml
  <VOUCHER ACTION="Create" VCHTYPE="Sales">
  ```

### 3.2 Internal Unique Identifiers
* **Tags Cleaned:**
  - `<GUID>...</GUID>`
  - `<MASTERID>...</MASTERID>`
  - `<ALTERID>...</ALTERID>`
  - `<VOUCHERKEY>...</VOUCHERKEY>`
  - `<VOUCHERRETAINKEY>...</VOUCHERRETAINKEY>`
* **Scope:** Cleaned within `<VOUCHER>...</VOUCHER>` blocks.
* **Why:** These are internal database primary keys generated by the source Tally database instance. Removing them ensures the destination Tally instance assigns fresh, non-conflicting IDs upon import.

### 3.3 ⚠️ CRITICAL CASE STUDY: The Stock Item "Primary Batch" Quantity Bug

> **Note for Future Developers:** This was a major production bug solved on October 13, 2026. Review this carefully before modifying stock item logic!

#### The Error Encountered in Tally Prime:
```
Line 1004: No QUANTITY given for 'Primary Batch' of 'Cane Jaggery 30kg'!
Line 4462: No QUANTITY given for 'Primary Batch' of 'J Goldd 50kg'!
...
```

#### Why did this happen?
In Tally XML, Stock Items with opening balances contain multiple interconnected tags:
```xml
<STOCKITEM NAME="Cane Jaggery  30kg">
  ...
  <OPENINGBALANCE> 90945.105 KG</OPENINGBALANCE>
  <OPENINGVALUE>-4226212.66</OPENINGVALUE>
  <OPENINGRATE>46.47/KG</OPENINGRATE>
  <BATCHALLOCATIONS.LIST>
     <GODOWNNAME>Main Location</GODOWNNAME>
     <BATCHNAME>Primary Batch</BATCHNAME>
     <OPENINGBALANCE> 90945.105 KG</OPENINGBALANCE>
     <OPENINGVALUE>-4226212.66</OPENINGVALUE>
     <OPENINGRATE>46.47/KG</OPENINGRATE>
  </BATCHALLOCATIONS.LIST>
  <TRADEREXCISEDUTIES.LIST>      </TRADEREXCISEDUTIES.LIST>
</STOCKITEM>
```

When a naive cleaner simply strips `<OPENINGBALANCE>...</OPENINGBALANCE>`, the resulting XML looks like this:
```xml
  <!-- NAIVE CLEANER RESULT (CAUSES CRASH) -->
  <BATCHALLOCATIONS.LIST>
     <GODOWNNAME>Main Location</GODOWNNAME>
     <BATCHNAME>Primary Batch</BATCHNAME>
     <OPENINGVALUE>-4226212.66</OPENINGVALUE>
     <OPENINGRATE>46.47/KG</OPENINGRATE>
  </BATCHALLOCATIONS.LIST>
```
Tally sees a `<BATCHALLOCATIONS.LIST>` block defining a batch named **"Primary Batch"**, but there is **no quantity** specified for it! Tally refuses to import this and halts with:  
`No QUANTITY given for 'Primary Batch' of '...'!`

#### The Correct Fix Implemented:
Inside every `<STOCKITEM>...</STOCKITEM>` block:
1. Strip `<OPENINGBALANCE>`, `<OPENINGVALUE>`, and `<OPENINGRATE>`.
2. Remove any populated `<BATCHALLOCATIONS.LIST>` sub-blocks completely.
3. Replace them with a clean, empty `<BATCHALLOCATIONS.LIST>      </BATCHALLOCATIONS.LIST>` structure right before `<TRADEREXCISEDUTIES.LIST>` or `</STOCKITEM>`.
4. Now Tally knows the item has no opening stock, and no orphaned batches remain.

```javascript
// Implementation in JS (index.html)
text = text.replace(/<STOCKITEM\b[\s\S]*?<\/STOCKITEM>/gi, (item) => {
  item = item.replace(/<OPENINGBALANCE\b[^>]*>[\s\S]*?<\/OPENINGBALANCE>\s*/gi, '');
  item = item.replace(/<OPENINGBALANCE\b[^>]*\/>\s*/gi, '');
  item = item.replace(/<OPENINGVALUE\b[^>]*>[\s\S]*?<\/OPENINGVALUE>\s*/gi, '');
  item = item.replace(/<OPENINGVALUE\b[^>]*\/>\s*/gi, '');
  item = item.replace(/<OPENINGRATE\b[^>]*>[\s\S]*?<\/OPENINGRATE>\s*/gi, '');
  item = item.replace(/<OPENINGRATE\b[^>]*\/>\s*/gi, '');
  if (/<BATCHALLOCATIONS\.LIST\b/i.test(item)) {
    item = item.replace(/<BATCHALLOCATIONS\.LIST\b[^>]*>[\s\S]*?<\/BATCHALLOCATIONS\.LIST>\s*/gi, '');
    if (/<TRADEREXCISEDUTIES\.LIST>/i.test(item)) {
      item = item.replace(/<TRADEREXCISEDUTIES\.LIST>/i, '<BATCHALLOCATIONS.LIST>      </BATCHALLOCATIONS.LIST>\n      <TRADEREXCISEDUTIES.LIST>');
    } else {
      item = item.replace(/<\/STOCKITEM>/i, '<BATCHALLOCATIONS.LIST>      </BATCHALLOCATIONS.LIST>\n     </STOCKITEM>');
    }
  }
  return item;
});
```

### 3.4 Ledger Opening Balances
* **Tags Cleaned:** `<OPENINGBALANCE>...</OPENINGBALANCE>` outside stock items.
* **Why:** In `<LEDGER ...>` blocks, `<OPENINGBALANCE>` specifies party debit/credit opening balances. Stripping this ensures that existing party balances in the target company are preserved and not overwritten.

---

### 3.5 Target Company Lock Removal
* **Tag Cleaned:** `<SVCURRENTCOMPANY>...</SVCURRENTCOMPANY>`
* **Why:** If the source export contains:
  ```xml
  <STATICVARIABLES>
     <SVCURRENTCOMPANY>FATHIMA TRADERS - May</SVCURRENTCOMPANY>
  </STATICVARIABLES>
  ```
  Tally will check if a company named `"FATHIMA TRADERS - May"` is active. If not, the import fails or prompts an error. Stripping this tag makes the XML company-agnostic so it can be imported into ANY active company.

## 4. 🔤 Character Encodings & Byte Order Mark (BOM)

Tally XML exports almost universally use **UTF-16 Little Endian (UTF-16LE)** with a 2-byte BOM:
- Byte 0: `0xFF`
- Byte 1: `0xFE`

If you re-save a UTF-16LE file as UTF-8 without updating the XML declaration, or if you save UTF-16LE without the BOM, Tally displays:
> `Cannot import file: Unrecognized XML format / Invalid encoding`

### How the Client-Side App Handles This:
1. **Inspection:** Reads the first 2 bytes via `Uint8Array(arrayBuffer)`.
2. **Decoding:**
   - If `0xFF, 0xFE` &rarr; decoded via `new TextDecoder('utf-16le')`.
   - If `0xFE, 0xFF` &rarr; decoded via `new TextDecoder('utf-16be')`.
   - Otherwise &rarr; fallback to `new TextDecoder('utf-8')`.
3. **Encoding for Download:**
   If the original was UTF-16LE, we must write back the `0xFF 0xFE` BOM and 2 bytes per char:
   ```javascript
   function encodeUtf16LE(str) {
     const buf = new ArrayBuffer((str.length + 1) * 2);
     const bytes = new Uint8Array(buf);
     bytes[0] = 0xFF; // BOM byte 1
     bytes[1] = 0xFE; // BOM byte 2
     const uint16 = new Uint16Array(buf, 2);
     for (let i = 0; i < str.length; i++) {
       uint16[i] = str.charCodeAt(i);
     }
     return bytes;
   }
   ```

## 5. 🛠️ How to Rebuild / Refactor ("അഴിച്ച് പണി")

If you are a developer hired to rebuild this application (e.g. converting to **Electron / Tauri desktop app**, or modernizing the web app with **React / Vue / Svelte / TypeScript**), follow these principles:

### Recommendation 1: Stream Parsing for Massive Files (> 150 MB)
- Currently, `index.html` loads the entire file into a JavaScript string and performs regex replacements.
- JavaScript V8 strings have a limit (~512MB depending on runtime). For files larger than 100MB, memory pressure can cause browser tabs to reload or freeze.
- **Modern Solution:** Use a **Web Worker** with a chunked streaming regex reader or a SAX-style streaming XML parser (`node-expat` or `sax-js` / Web Streams API) so processing takes minimal RAM regardless of file size.

### Recommendation 2: Packaging as Desktop App (Tauri / Electron)
- Accountants frequently prefer a standalone desktop application (`.exe`) that doesn't need a browser.
- **Tauri (Rust + Web Frontend):** Recommended because the executable size will be < 10MB, with direct native file read/write access and no need to re-download files into `Downloads`.
- **Python (PySide6 / PyQt):** The existing `gemini-code-1791868496368.py` can easily be wrapped with a GUI.

### Recommendation 3: Configuration Presets
Allow users to toggle presets:
- **Preset 1 (Full Merge):** Remove IDs + Remove Opening Balances + Remove Company Lock (Default).
- **Preset 2 (Masters Migration Only):** Keep Opening Balances, only remove GUIDs/MasterIDs.
- **Preset 3 (Custom Filter):** Let the user choose specific voucher types (e.g. Sales only, Purchase only).

## 6. 📝 Rules for Future Developers (Mandatory!)

Whenever you make ANY update, bugfix, or feature addition to this project:
1. **Never alter encoding without verification:** Always test your output XML with both UTF-16LE and UTF-8 in a real Tally instance.
2. **Never delete `<OPENINGBALANCE>` without cleaning `<BATCHALLOCATIONS.LIST>`:** Remember the Primary Batch bug (Section 3.3).
3. **Always update `CHANGELOG.md`:** Document the problem, the root cause, and the fix in clear English (with Malayalam summary if helpful).
4. **Update `DEVELOPER_HANDBOOK.md`:** If new tags are added to the cleaning list, add a subsection explaining what the tag does in Tally and why it had to be cleaned.
5. **Keep zero-tracking / privacy pledge:** This tool handles sensitive company balance sheets, GSTINs, and revenue figures. Never introduce remote API calls, analytics, or external server uploads. Everything must run local.
